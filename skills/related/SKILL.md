# 查找相关工作（本地 + 网络）

CLI：`node "${CLAUDE_SKILL_DIR}/../../bin/pv.mjs"`（下文记作 `pv`）。如果 `${CLAUDE_SKILL_DIR}` 没有被替换成真实路径，就用本 skill 所在目录往上两级的 `bin/pv.mjs`。

用户要做的事：$ARGUMENTS

## 步骤

1. 把任务拆成 3-6 个子主题（问题设定、方法路线、所用模型、评测基准等），每个子主题准备中英文关键词。
2. **本地**：每个子主题跑 `pv search "<关键词>" --json --top 10`；库不大时再通读 `pv catalog`。读相关候选的总结文件，确认相关性，并记下每篇和用户任务的关系（同问题不同方法 / 可借用的方法 / 可比的 baseline / 用到的基准）。
3. **网络**：用 WebSearch（必要时 WebFetch 打开 arXiv、Semantic Scholar、项目主页）按子主题搜索，重点找：
   - 近两年的代表性工作和最新进展；
   - 本地论文引用或被引用的关键工作；
   - 本地库里明显缺的方向。
   对每篇网络结果核对标题、作者、年份、链接确实存在，不要凭记忆编造论文。和本地库重复的（标题或 arXiv 号相同）不要再列。
4. 回复结构：
   - **库里已有**：按子主题分组，每篇一行：标题（年份）— 和任务的关系 — 总结文件链接。
   - **库里没有、建议补充**：按子主题分组，每篇一行：标题（年份，会议）— 一句话说明 — 链接；标出最值得读的 3-5 篇。
   - **空白与建议**：现有工作没覆盖、用户任务可以切入的地方（2-4 条）。
5. 最后问用户是否要把“建议补充”里的某些论文下载到 inbox。用户同意后，只从 arXiv（`https://arxiv.org/pdf/<id>`）或论文官方页面下载 PDF 到 `<论文库>/inbox/`（`pv where` 可查目录），文件名用 `<arxiv号>.pdf`；inbox watcher 会自动总结入库，没开 watcher 时用 add skill 处理。
